# نشر المرحلة الثالثة

## المستودع

المستودع المستهدف هو `Viciniio/gpc-connect-five-9x7`، والفرع `main`.

## المتطلبات داخل GitHub

- المستودع عام (للاستفادة من مشغلات Linux القياسية المجانية للمشروعات العامة).
- Actions مفعّل.
- يحتاج workflow إلى `contents: write` لإنشاء GitHub Release ورفع checkpoint assets.
- يستخدم كل عامل `GITHUB_TOKEN` الخاص بجولة Actions؛ لا يوجد PAT ثابت ولا سر شخصي مطلوب.

## بدء العمل

1. انشر ملفات الحزمة إلى `main`.
2. سيبدأ Workflow تلقائيًا بسبب `push` على مسارات المشروع.
3. أو افتح `Actions` ثم `GPC Phase 3 — Distributed Mathematical Proof` ثم `Run workflow`.
4. سيُنشأ Release باسم `gpc-phase3-checkpoints`.
5. ستبدأ 21 مجموعة؛ يسمح `max-parallel: 20` بتشغيل عشرين منها بالتوازي.
6. بعد انتهاء العمال أو فشل بعضها، يحاول المجمّع بناء شهادات الجذر من النتائج المتاحة، ويكتب `game_value_report.json`.

## استمرار جولة لاحقة

أعد تشغيل Workflow بنفس المستودع والوسم. كل عامل يستعيد الـmanifest والفتحة النشطة من Release. لا تحذف Release أو أصوله ما دامت هناك أعمال غير محسومة.

## الأمان والتحكم

لا تحتوي الحزمة على مفاتيح وصول أو كلمات مرور. صلاحية الكتابة المطلوبة محصورة في Actions token المؤقت وصلاحيات الـworkflow الموضحة أعلاه. الشيفرة في مستودع عام؛ لا ترفع إليها معلومات شخصية أو أسرارًا.
